HOW IT WORKS

A clear path from AOI to GIS layers.

The plugin combines your area of interest and selected feature categories into an Overpass request, then organises the returned OSM features for export.

THE DOWNLOAD JOURNEY

Six steps, from map to layers

Use the sequence below as a practical guide to a typical download in QGIS.

  1. 01

    Define the area of interest

    Use the current QGIS map extent, draw a rectangle, use the bounding box of selected features, or take the active layer's extent. Review the displayed south, west, north and east coordinates.

    Compare AOI methods →
    AOI
  2. 02

    Select the OSM categories

    Tick the feature groups you need. Select All and Clear All help manage the list. For administrative boundaries, choose the required admin_level values or leave all levels enabled.

    Review supported categories →
    CATEGORIES
  3. 03

    Configure output options

    Choose GeoPackage or Shapefile, select an output directory, and decide whether to add finished layers to QGIS automatically and reuse the local cache where available.

    Compare file formats →
    OUTPUT
  4. 04

    Start the Overpass download

    Click Download OSM Data. Enter a city, country, region and area name in the naming dialog, then continue to download. The values are joined to form the output base name.

    REQUEST
  5. 05

    Process and organise returned features

    The plugin classifies returned OSM elements into the selected categories and separates results by geometry. Multipolygon relations are assembled into polygons with holes where the data allows. Progress is shown in the Processing Log.

    PROCESS
  6. 06

    Load and use the resulting layers

    Output is written as a GeoPackage or Shapefile layer sets. When automatic loading is enabled, completed layers are added to the current QGIS project.

    See layer naming conventions →
    QGIS

UNDER THE HOOD

How the Overpass request is handled

The plugin uses the public Overpass API to retrieve matching OpenStreetMap elements for the selected area and categories.

01

Request the selected data

The plugin submits a request for the chosen AOI and categories to the Overpass API. Each request allows up to 300 seconds.

02

Try alternate servers when needed

The first endpoint is overpass-api.de. If a server fails after retrying, the plugin can fall back to lz4.overpass-api.de and overpass.kumi.systems.

03

Classify and prepare geometry

Returned elements are matched to the selected categories and written into the appropriate point, line or polygon layers. Multipolygon relations are assembled where the data allows.

04

Stage, export and clean up

The plugin first writes to a temporary GeoPackage in the output folder, converts it to the chosen format, and removes only temporary files matching .osm_toolkit_temp_*.gpkg.

OUTPUT OPTIONS

Choose the right container

Both formats are supported, but their ability to retain attributes differs. GeoPackage is recommended when you need all OSM tags.

GPKG

GeoPackage

Recommended
  • All output layers are stored in one .gpkg file.
  • All OSM tags are retained.
  • Text fields have no fixed Shapefile-style 254-character limit.
  • Suitable for larger requests with many different tags.
SHP

Shapefile

  • Each layer is written as a separate Shapefile set.
  • Text fields are limited to 254 characters.
  • Column and record-size limits can prevent every tag column from being retained.
  • Use when a downstream workflow specifically requires .shp.

LARGE-AREA DOWNLOADS

Make requests easier on shared servers.

Large areas can produce much larger responses, particularly when buildings and roads are included. The public Overpass servers are shared infrastructure.

01

Keep the AOI focused on the area you need.

02

Tick only the categories required for the task.

03

Split very large regions into smaller rectangles.

04

Prefer GeoPackage when all tags matter, and retry later if public servers are busy.
